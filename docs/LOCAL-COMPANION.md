# 可选的本机小G连接

角色、六档形态、手动互动和 Codex 工作状态可独立运行。聊天、记忆、养成、主动来信和提案通知由另外运行的兼容小G服务提供，本仓库提供对应客户端。

## 连接方式

服务固定监听 `http://127.0.0.1:8766`。启动服务后，右键“和小G聊聊”打开原生聊天窗；“陪伴设置”可暂停连接或管理消息与回复动作。

需要桌宠协助启动已有服务时，在运行目录 `bin` 中自行创建 `companion-link.json`：

```json
{
  "projectDirectory": "<小G服务项目的绝对路径>",
  "pythonExecutable": "<该项目环境中 python.exe 的绝对路径>"
}
```

填入实际路径，使用正斜杠可减少 JSON 转义。桌宠仅调用指定项目的 `app.py --port 8766`，Python 可执行文件名需为 `python.exe`。该文件属于个人配置，不提交到公开仓库或分发包，更新程序保留已有文件。

## 客户端协议

| 请求 | 用途 |
| --- | --- |
| `GET /api/pet` | 协议版本、对话、任务、互动、养成和通知快照 |
| `POST /api/life/chat` | 提交消息并取得任务编号 |
| `POST /api/life/browse` | 现有的视频读取入口 |
| `POST /api/pet/interaction` | 记录摸头、喝茶、投喂等互动 |
| `POST /api/review/notifications/seen` | 标记明确查看过的结果 |

快照使用 `protocol: 1`。基础字段为 `messages`、`jobs`、`recent_jobs`；新版本可提供 `pet_state`、`interaction` 和 `review_inbox`。消息包含 `id`、`role`、`kind`、`text`、`emotion`；通知包含稳定编号、版本及对应结果身份。

客户端使用固定回环地址、请求路径白名单和关闭重定向的连接方式。查看入口只记录已读；提案批准和执行继续遵循后端的明确授权。

## 使用与数据

聊天使用所配置后端的模型账号与额度。服务未就绪时，聊天窗显示连接状态，桌宠基础功能继续运行。关闭桌宠不会关闭独立运行的小G服务。

聊天和记忆由服务维护，桌宠保留显示游标与连接偏好。首次连接不重播旧来信。安静模式、睡眠和拖动期间，会抑制不合时宜的主动气泡或回复动作。
