# 性能与验收记录

验证日期：2026-10-19。本机 Windows、.NET Framework 4.8；默认可见窗口、6 fps 慢速浮动、Codex 工作状态连接开启，未关闭角色或强制裁剪工作集。

| 构建 | CPU 平均（整机逻辑核归一） | 工作集平均 | 专用内存平均 | GPU 引擎平均 |
|---|---:|---:|---:|---:|
| 旧版稳定采样 | 0.462% | 100.92 MB | 99.27 MB | 8.22% |
| 0.2.0，含新托盘图标 | 0.015% | 89.28 MB | 71.25 MB | 1.3% |

每轮为预热后 25 个约一秒的样本。GPU 取该进程所报告的最忙引擎，不包括 Windows 桌面合成器以及短暂运行的 Codex 查询子进程；不是整机增量功耗测试。不同硬件、缩放比例、窗口大小和操作会改变结果。不可用计数器记为 null，不视为 0。原始记录留在本地 verification/，不上传聊天信息或本机进程标识。

保留的优化：后台浮动限制为 6 fps、安静模式 3 fps；短动画 24 fps；隐藏时停止持续动画；复用日志缓冲区和未变化的额度控件；已有新鲜聊天额度时不再重复启动查询进程。默认 x86 构建降低了本机测得的专用内存占用，仍支持通过构建参数生成 AnyCPU/x64 版本。

## 功能验收

25 项核心检查与 18 项原生 WPF 界面检查通过，覆盖任务开始/结束/中断、重复提醒抑制、公开完成摘要、空额度、旧额度覆盖防护、UTF-8 分段与日志截断、实时文件监听、摸头、私有设置目录、气泡收起、鼠标穿透及恢复、工作面板、设置持久化、减少动画、隐藏/恢复、完成庆祝与托盘图标加载。

独立隔离会话验证了“写入工作事件 → 工作姿态与额度进入界面 → 写入完成事件 → 庆祝姿态、结果气泡与通知回调”。实际账号也成功读取了 Codex 额度。程序已实际启动；重复启动不会产生多个桌宠实例。

系统托盘图标与声音的最终显示/可闻性还受 Windows 通知设置及音频设备影响。
