# 测试说明

在 Windows 的交互式桌面会话中执行：

```powershell
./build.ps1 -Test -UiTest
```

构建前应退出已运行的程序，或使用 `-OutputDirectory` 指定独立输出目录。默认使用 x86；`-Platform anycpu`、`-Platform x64` 可覆盖。

## 本次验证

- 25 项核心检查全部通过，涉及日志生命周期、通知去重、完成摘要、额度解析、缺失值、旧数据覆盖防护、截断和 UTF-8 增量写入等。
- 18 项 WPF 界面集成检查全部通过，涉及可见窗口、新托盘图标、工作与完成姿态、真实文件事件进入界面、摸头回应、鼠标穿透与恢复、面板、设置保存/重载、减少动画、隐藏/显示、气泡自动收起与完成摘要。
- 测试以临时 `CODEX_HOME` 和独立的 `CODEX_PET_DATA_DIR` 运行，不修改真实聊天或用户设置。为避免人工点击干扰计时，测试窗口禁用外部命中测试，由测试向实际 WPF 控件发送路由事件；这不是对全部鼠标手势的人工回放。
- 在真实 Codex 环境中另行实际启动，确认窗口可见、当前聊天被跟随、账户额度查询成功；重复启动只保留一个桌宠实例。
- 自动联动程序已安装并运行，探测到实际 Codex 桌面宿主。另用隔离窗口宿主触发真实 Windows 前台激活事件，确认桌宠自动启动；第二个宿主窗口不会重复启动桌宠。此过程没有关闭实际 Codex。
- 实际执行了关闭联动与重新安装：关闭后联动进程和对应的用户登录启动快捷方式被移除，桌宠仍运行；重装后联动恢复。
- 资源测量方法与结果见 [PERFORMANCE.md](PERFORMANCE.md)。

## 0.2.1 安装包验收

已用生成的安装 EXE 实际执行当前用户静默安装，目标目录包含中文和空格。验证了桌面与登录启动快捷方式、卸载注册信息、安装后的原生窗口及新托盘图标。随后在原目录重装，验证关闭自动联动会停止辅助进程并移除对应启动项，再次启用后恢复。

实际卸载后，程序文件、对应进程、启动快捷方式和卸载注册信息均被清除；桌宠个人设置和用户额外放入安装目录的文件保留，Codex 桌面应用仍在运行。本机原有源码版及其自动联动在验收结束后恢复。安装器 GUI 的每个向导按钮未逐一模拟点击，安装路径与任务选择通过标准静默参数验证。

本地证据位于 `verification/`，可能包含聊天标识、设备进程信息或公开工作消息，因此不上传。仓库提供可重跑的测试源码，而非这些本机数据。

## 0.2.2 AI 安装与联动复查

从公开 GitHub API 匿名发现最新安装包、下载并核对 SHA-256，再执行当前用户安装。复现了 0.2.1 的缺陷：桌面宿主复用进程、新开窗口时，仅按进程编号去重会漏掉启动。0.2.2 同时识别窗口句柄，保留单实例行为。

`tests/LinkIntegration.ps1` 通过真实 Windows 前台激活事件测试新进程窗口、同进程新窗口及重复启动；可传入实际 Startup 快捷方式。测试只关闭参数指定目录内的桌宠与辅助进程，使用隔离设置及聊天目录；发现其他安装副本正在运行时会中止。

```powershell
./tests/LinkIntegration.ps1 -BinaryDirectory ./bin -EvidenceDirectory ./verification/link-test-new
```

执行前应退出其他目录中的桌宠与联动程序。真实 Codex 已有可见窗口时，还会验证重启联动程序后能带起桌宠。本次另外从 Windows 已注册的应用入口实际打开 Codex，确认安装目录中的桌宠自动启动；没有强制关闭 Codex或重启 Windows。完整 Windows 注销再登录的过程未实际执行。
